# B 站自主浏览与评论

<p align="center"><img src="icon.png" width="128" height="128" alt="B站自主浏览与评论图标"></p>

> **Version:** 0.8.15 · MaiBot 1.3.10～1.4.8 · Python ≥ 3.10 · SDK ≥ 2.12.0

麦麦独立插件 `local.bilibili-autopilot`（归类为 `integration`）。登录指定 B 站账号后，默认自动进入自主模式：麦麦会结合自身人设、兴趣、时段与近期反馈自主决定是否刷 B 站，阅读视频摘要或字幕后判断是否发表评论、跟进回复或分享到 QQ 群。

- 详细配置示例：[config.example.toml](config.example.toml)
- 更新日志：[CHANGELOG.md](CHANGELOG.md)

## 核心功能一览

- **自主浏览决策**：读取账号首页推荐并过滤广告、直播、重复视频、过长视频、屏蔽词与指定 UP 主。自主模式下先由模型判断“刷不刷”以及下次检查时间（持久化保存，重启不重刷）；不启动播放器，也不上报播放时长或污染账号观看历史（当前不读取群聊忙碌状态或真实情绪）。
- **基于内容理解的评论**：优先读取 B 站 AI 摘要，缺失时提取字幕并在拟写评论时按主题补充复核；无足够文本依据或多 P 视频直接跳过，不凭标题编造观后感，不做音频转写或画面分析。
- **人设驱动与依据校验**：沿用麦麦的 `personality` 与 `reply_style`（可叠加额外兴趣与评论风格），允许自然“看过不评论”；发表前对模型结构化输出及引用原文进行校验，仅达到兴趣阈值时才考虑评论。
- **回复跟进与群分享**：可自动检查并接话别人对麦麦已发送评论的回复；支持在评论成功后将视频以 QQ 小程序卡片（或链接）搭配看点感想分享到指定 QQ 群。插件不点赞、不投币、不发送弹幕。
- **自然语言回忆 B 站经历**：提供只读工具 `bilibili_autopilot_history`，支持在聊天中直接询问麦麦最近刷过的视频、发表的评论及回复记录，区分真实发送、预览草稿与未知结果。

## 安装与快速开始

### 1. 安装插件

- **方式 A：插件市场（推荐）**
  在 MaiBot WebUI 插件市场搜索 **B站自主浏览与评论**，选择与宿主兼容的版本安装。版本列表来自已被市场收录的 GitHub Release（仓库提交或打 Tag 不会立即上架）。

- **方式 B：手动安装**
  在 MaiBot 根目录执行：
  ```sh
  git clone https://github.com/namchengwuqiu/bilibili_autopilot.git plugins/local_bilibili_autopilot
  ```
  重新加载插件或重启 MaiBot，Host 会自动按清单安装依赖；如需手动安装依赖，可在 MaiBot 使用的 Python 环境中执行：
  ```sh
  uv pip install -r plugins/local_bilibili_autopilot/requirements.txt
  ```
  Docker 部署可将仓库放到挂载至容器 `plugins/` 的目录并在容器环境中安装依赖，无需改动麦麦主程序。

### 2. 首次配置五步走

1. **确认加载**：在麦麦 WebUI 插件管理中确认插件加载成功，并打开插件配置页面。
2. **设置管理员**：填写 `plugin.admin_users`（QQ 管理员可直接填 QQ 号如 `["123456"]`，保存时自动补全为 `["qq:123456"]`；其他平台填 `平台:用户号`）。留空时普通聊天命令一律拒绝（Host 验证的本地操作员仍可管理）。
3. **扫码登录**：**私聊**麦麦发送 `/bili_auto login`，在 3 分钟内使用 B 站客户端扫码确认。凭据仅写入本插件私有数据目录，不读取其他插件账号。登录后默认自动启动自主浏览（关闭 `browse.auto_start` 则需手动 `start`）。
4. **预览效果**：默认关闭自动发表评论（`comment.publish_enabled = false`）。可发送 `/bili_auto preview` 直接跳过意愿判断预览一轮选片与评论效果（不实际发出评论）。
5. **按需开启发布**：确认风格与效果满意后，开启 `comment.publish_enabled`。可随时通过 `/bili_auto status` 查看运行状态与下次检查时间，通过 `/bili_auto history` 查看最近决定与视频记录。

> **运行状态说明**：手动 `pause`、退出账号或异常暂停都会持久化保留，不会被 `auto_start` 自动解除，排除后需发送 `/bili_auto start` 恢复；关闭 `browse.autonomous_enabled` 后则按固定间隔浏览。自动轮次记录写入本地并通过 `history` 或 WebUI 查看，不主动向群聊刷屏汇报。

### 3. 管理指令速查

| 指令 | 用途说明 |
| :--- | :--- |
| `/bili_auto login` | 仅限私聊执行，生成二维码扫码登录（3 分钟有效） |
| `/bili_auto preview` | 立即浏览一轮并生成评论草稿，**仅预览不发表** |
| `/bili_auto replies` | 检查别人对麦麦的回复并预览是否接话，**不实际发送** |
| `/bili_auto start` | 在手动或异常暂停后恢复运行（仍由麦麦自主决定是否立刻刷） |
| `/bili_auto pause` | 暂停自动浏览与回复检查（已发出的请求可能继续完成，不再发起下一条） |
| `/bili_auto status` | 查看当前账号、运行状态、今日额度、异常原因及最近意愿决定/下次检查时间 |
| `/bili_auto history` | 查看最近 3 次自主浏览决定及视频处理记录 |
| `/bili_auto logout` | 暂停运行并清除本插件登录态（保留去重历史） |
| `/bili_auto ack BV号` | 自行到 B 站核对未知发送结果后解除发送阻塞（该视频仍不会重发） |

### 4. 扫码登录失败排查

- 自 **0.8.6** 起，登录日志以 `B站登录诊断` 标记二维码生成、轮询、账号验证与凭据落盘阶段（仅在状态变化时打印），不输出 Cookie、二维码密钥、代理地址或本地证书路径等敏感信息。
- 自 **0.8.8** 起，登录全流程与 B 站读取/签名均统一使用开启 TLS 证书与主机名校验的 `httpx` 客户端（避免旧版 `curl_cffi` 在中文/特殊路径或缺少证书时出现 `code=77`）。
- 若登录异常，请先更新到最新版本并重载，确认日志包含 `client=httpx`；若仍失败，请附上本次 `B站登录诊断` 开始至失败的日志片段及管理页错误摘要反馈（切勿关闭证书验证或上传登录凭据）。

## WebUI 扩展管理页

麦麦 WebUI 侧栏 **「插件扩展 → B站自主浏览管理」**（路由 `/extensions/local.bilibili-autopilot/manage`）复用宿主登录权限，无需额外部署网页服务：

- **状态与操作面板**：查看账号、启停状态、今日分析/评论额度、最近自主决定、暂停原因、下次检查时间与最早可再次评论时间；支持一键恢复、暂停、预览、检查回复（仅预览）、扫码登录/退出及输入 `/bili_auto` 指令。页面操作不会往 QQ 群发消息，刷新只读本地状态。
- **模型用量统计（最近 7 天）**：顶部可展开查看当前账号每日模型调用次数、有 Usage 记录的次数及输入/输出/总 Token（含失败、超时与取消调用，实际费用以模型服务商账单为准）。
- **记录检索与核对**：按当前 B 站 UID 隔离，分页检索视频浏览、评论发送、自主决定、收到的回复、跟进回复与群分享记录，明确区分拟写草稿与实际提交结果。支持对最近一条一级评论点击 **「核对最近评论的公开可见性」**（先以访客查询，查不到再以发布账号复核，只读不重发），以及针对未知结果填写 BV 号确认解除阻塞。
- **表格横向滚动说明**：视频与回复记录保留完整 13 列字段。长表横向滚动由 MaiBot 主程序 WebUI 提供（见 [MaiBot PR #2208](https://github.com/Mai-with-u/MaiBot/pull/2208)）；旧版 Dashboard（如 1.9.4）可能出现列挤压，需升级包含补丁的宿主前端资源并刷新缓存。

## 核心工作机制

### 1. 自主浏览、候选池与模型调度

- **浏览节奏**：`browse.interval_seconds`（默认 600 秒）与 `browse.max_check_minutes`（默认 20 分钟）决定意愿检查范围，到期时先拉取一次首页推荐标题/简介/时长供模型判断是否想刷；选择休息时不读取字幕或摘要，也不消耗每日视频分析额度（`videos_per_day` 默认 180）。
- **探索开关**：开启 `browse.explore_more` 后，当存在感兴趣的新推荐时麦麦更倾向先看一两条，不会因近期未评论或手动预览而长期休息（不强制发表评论；评论门槛由 `comment.min_interest` 单独控制，默认 `0.75`）。
- **候选池机制**：评论额度用完或处于冷却期（默认 45 分钟）时，若已有 6 条有效候选则暂缓新分析；不足时仅做兴趣判断并存入候选池（默认上限 `24` 条、有效期 `48` 小时，超限按兴趣、新鲜度与等待时间择优保留）。冷却结束且有额度时，模型从至多 10 条候选中择优挑 1 条**重新读取正文、生成并复核**后决定是否发表，不直接发送旧草稿。
- 评论与回复默认由 `replyer` 生成。浏览意愿、候选选片和正文依据复核优先使用 `utils`。模型超时或回答格式无效时，插件按顺序尝试后续候选，并在该阶段的剩余时限内给后续候选留出时间。模型明确选择休息、放弃选片或判定正文缺乏依据时，该判断立即生效。

### 2. 跟进别人对麦麦的回复

- 默认开启 `replies.enabled`，每 10 分钟检查一次“回复我的”通知（受活动时段、暂停状态与独立每日限额控制，默认每天最多分析 20 条、发送 8 条）。
- **严格楼层边界**：仅处理他人直接回复**本插件已成功提交的评论**或后续楼层互动，不接管手工评论、未确认发送、无关楼层、私信或单独 @。
- **频率与时效**：仅跟进最近 `72` 小时内通知（最多翻 3 页）；距离最近一次评论/回复发送至少间隔 `15` 分钟；同一根评论下长期累计最多跟进 `3` 次（失败也计入）。可通过 `/bili_auto replies` 预览而不发送。

### 3. 评论后分享视频到群

- 配置 `[share].qq_group_ids`（最多 10 个麦麦已加入的 QQ 群，默认空不分享）后，**仅当视频一级评论实际提交成功**时触发（预览、跳过、被限额拦截、结果待核对或跟进回复均不触发）。
- 生成“具体看点 + 分享原因”（50～120 字，最多 180 字）并通过依据复核后，默认先发 QQ 签发的 B 站小程序卡片（无“打开 B 站 App”按钮，可复制 BV 号），回读确认卡片与地址无误后再发送感想；关闭 `miniapp_enabled` 则发送“感想 + 官方链接”。
- 按 `(B站UID, 视频, QQ群)` 持久化去重，每群仅尝试一次，群消息失败不自动重发，也不影响已成功的 B 站评论。

### 4. 在聊天中回忆 B 站活动

- 插件提供只读工具 `bilibili_autopilot_history`，聊天模型可在用户询问「最近刷了什么 B 站视频？」「你在某某视频下评论了什么？」时按标题、UP 主、BV 号或关键词检索本地持久化记录（默认最近 7 天、最多 8 条，`days=0` 可查全部）。
- **事实交接钩子**：查询成功后，插件会在回复前将真实标题、评论正文、内容依据与发送状态注入回复模型，避免规划器转述丢失事实（同一上下文仅对当前目标问题有效且最多保留 5 分钟）。即使用户明确追问时规划器未重新调用工具，回复前也会自动从本地库补充事实；无关闲聊不附加历史。
- **边界说明**：不把后台 B 站活动伪造为 QQ 聊天记录或写入宿主通用记忆库；未登录或禁用插件时不返回历史；平台回执仅代表 B 站已接收，不保证公开可见。

## 配置参考

以下为默认配置结构，完整注释请参考 [config.example.toml](config.example.toml) 或直接在 WebUI 配置页编辑。

### `[plugin]` - 插件基础

| 配置项 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `enabled` | `true` | 是否启用插件；关闭后停止后台浏览与检查 |
| `config_version` | `"0.3.0"` | 配置格式版本（只读，由插件维护） |
| `admin_users` | `[]` | 管理员列表，QQ 号自动补全为 `qq:号码`，其他平台填 `平台:用户号` |

### `[browse]` - 浏览与筛选

| 配置项 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `auto_start` | `true` | 登录后自动开启自主浏览；手动暂停或异常暂停需 `start` 恢复 |
| `autonomous_enabled` | `true` | 是否由模型自主决定“刷不刷”及等待时间；关闭后按固定间隔执行 |
| `explore_more` | `false` | 更积极探索新视频，减少因近期未评论或手动预览导致的连续休息 |
| `interval_seconds` | `600` | 最短浏览意愿检查间隔（秒，最小 300） |
| `decision_retention_days` | `0` | 自主决定历史永久保留。设为正数后按天清理，每个账号至少保留最新一条 |
| `max_check_minutes` | `20` | 最长浏览意愿检查间隔（分钟，5～360） |
| `videos_per_round` | `3` | 每轮最多分析视频数（1～10） |
| `videos_per_day` | `180` | 每日视频分析上限（含手动预览） |
| `max_per_up` / `max_per_topic` | `2` / `2` | 每轮同一 UP 主 / 同一已知分区题材的视频上限（1～10） |
| `max_duration_seconds` | `1200` | 超过该时长的视频跳过（秒，30～7200） |
| `interests` | `""` | 额外偏好话题说明，留空则结合麦麦人设与账号推荐判断 |
| `blocked_keywords` | `[]` | 标题、简介或正文命中任意关键词则跳过 |
| `blocked_up_uids` | `[]` | 屏蔽的 UP 主数字 UID 列表 |
| `active_start_hour` / `active_end_hour` | `9` / `23` | 活动时段（24 小时制，结束小时为开区间；相等表示全天，支持跨午夜） |
| `timezone` | `"Asia/Shanghai"` | 活动时段与每日统计零点时区 |
| `backlog_max_items` | `24` | 评论候选池最大容量（1～100） |
| `backlog_max_age_hours` | `48` | 评论候选最长保留小时数（1～168） |
| `read_retry_base_seconds` | `60` | 可重试网络错误首次退避秒数（10～600） |

### `[comment]` - 一级评论控制

| 配置项 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `publish_enabled` | `false` | **总发布开关**，关闭时后台浏览仅生成预览草稿不实际发表 |
| `per_day` | `12` | 每日一级评论发送尝试上限（1～200，失败或未知也计次） |
| `min_interval_seconds` | `2700` | 发表一级评论前距最近一次评论或跟进回复的最短间隔（秒，默认 45 分钟） |
| `max_chars` | `160` | 单条评论最大字数（20～500，超出直接跳过不截断） |
| `min_interest` | `0.75` | 最低兴趣分门槛（0～1，越高越挑剔） |
| `similarity_threshold` | `0.88` | 与近期历史评论相似度阈值（0.5～1，越低查重越严格） |

### `[model]` - 模型与依据复核

| 配置项 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `task` | `"replyer"` | 使用的 MaiBot 模型任务名 |
| `candidates` | `[]` | 候选具体模型名列表（按顺序失败切换，留空则由任务选模） |
| `fast_task` | `"utils"` | 快速判断任务。留空后直接使用主任务及其候选模型 |
| `fast_candidates` | `[]` | 启用快速任务时优先尝试的模型。留空时由快速任务选模 |
| `timeout_seconds` | `90` | 单个候选模型等待超时（秒，10～180） |
| `decision_budget_seconds` | `240` | 单条评论/回复从生成到复核总预算（秒，20～900） |
| `review_timeout_seconds` | `45` | 单次正文依据复核超时（秒，1～120） |
| `evidence_retention_days` | `7` | 内容依据摘录与时间位置缓存天数（1～30） |
| `extra_style` | `""` | 附加评论风格提示（如“简短自然、少用表情”） |
| `content_max_chars` | `12000` | 提供给模型的摘要与字幕总字符上限，含字幕时间标签和换行 |

### `[replies]` - 回复跟进

| 配置项 | 默认值 | 说明 |
| :--- | :--- | :--- |
| `enabled` | `true` | 是否开启后台回复跟进（实际发送仍受 `comment.publish_enabled` 控制） |
| `interval_seconds` | `600` | 通知检查间隔（秒，默认 10 分钟） |
| `per_day` | `8` | 每日跟进回复发送尝试上限（1～200） |
| `analyses_per_day` | `20` | 每日收到回复分析上限（预览也计次） |

## 异常恢复、数据存储与权限安全

### 发送防重与失败恢复

- **防重复发送护栏**：每次发表评论或跟进回复前先以 SQLite 事务记录意图并校验限额与间隔，签名 POST 请求**仅调用一次**。超时、进程中断（重启时 `pending` 自动转为 `unknown`）或回执不明时标为 `unknown`，**绝不自动重试**。
- **`unknown` 状态的范围**：仅暂缓后续评论与跟进回复发送，不暂停自主浏览或手动预览；待人工确认 B 站实际结果后，在管理页或通过 `/bili_auto ack BV号` 解除阻塞（解除后原视频仍保持去重不重发）。
- **读取与生成容错**：
  - 读取视频内容或补充字幕时，B 站返回 `62012` 表示稿件仅 UP 主可见。插件在浏览记录中写明跳过原因，结束该视频的自动重查，并继续处理其他候选。
  - AI 摘要遇 `code=-504`、网络超时或连接失败时自动降级读取字幕；遇 HTTP 401/403/412/429 风控或登录失效则立即暂停，不绕过限制。
  - 遇到模型内容审核拦截（HTTP 451）跳过且不再自动重查；明确未发送的临时读取失败、模型超时或校验不通过，将在至少等待 10 分钟后重查 1 次，第二次失败后至少等 20 分钟（最多再查 2 次，计入当日分析额度）。
  - 分析阶段中断会在下次加载时恢复未发送任务，计 1 次失败且不重复累加。

### 数据目录与安全边界

- **本地数据存储**：数据保存在宿主分配的 `ctx.paths.data_dir`，核心文件为 `credential.json`（仅当前用户可读写的本地登录凭据，请妥善保护运行目录）与 `state.sqlite3`（自主决定、冷却时间、历史与依据缓存，按 B 站 UID 隔离）。日志不打印 Cookie、完整请求参数或模型提示词。
- **权限与配置安全**：插件仅申请模型生成、人设读取、文字/图片/自定义消息发送、API 调用与已有 QQ 群会话查询能力。`config.toml`、数据库、`credential.json` 与二维码截图均属于本地敏感文件，**请勿提交或公开发布**。
- **第三方声明**：本插件为第三方社区扩展，与哔哩哔哩官方无隶属关系，接口可用性受 B 站平台策略与 `bilibili-api-python` 适配影响。
